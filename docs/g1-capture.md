# G1: XR capture and desktop fallback

Owner: Gloria. Binding plan: [v2, 25 November 2026](plan/SeeSaw_Implementation_Plan_v2.pdf), pages 3–6, 8, 10–11. This is a first implementation increment, not completed A1/A2 acceptance. No code or scenes from the earlier demo branches are reused.

## Run without a headset

Use **Godot 4.7.2-stable**, standard build (the pin proposed in PR #3). Import `godot/project.godot` and run it. Desktop is the default; no headset or sidecar is needed and OpenXR is not requested.

Controls: WASD moves horizontally; hold right mouse to look; left click or Space captures; Escape releases the mouse; P exports the most recent PNG and JSON context to Godot's `user://captures` directory (the on-screen message gives the absolute location). A supplied depth map is also exported as EXR. The square preview shows the captured view, not the current view.

The four unshaded panels are a G1 calibration fixture (red/green above blue/mid-grey). They are not DemoWorld. The debug text/preview is a desktop harness, not Yernur's latency HUD. No backend inference or overlay is claimed.

The capture camera follows the head pose. Desktop mouse aim and XR right-controller aim select a world point; they do not turn the capture camera. The square 70-degree capture projection intentionally differs from the desktop window and the XR per-eye views. Only render layer 1 is captured; reserve other layers for controller visuals, HUD and lens.

## Quest session (pending)

On the lab PC, configure the team's OpenXR runtime and connect the Quest 3S. Launch:

```text
godot --path godot --xr-mode on --rendering-method gl_compatibility
```

Both controllers use the `aim` pose. The right controller's `trigger_click` requests a capture, provided head and controller tracking are present. The committed OpenXR map is generated by Godot 4.7.2's default action-set generator, including Oculus Touch bindings; lens actions must be requested from Gloria. The desktop default avoids the missing-HMD startup warning. `--xr-mode on` can still show it when hardware/runtime is absent; use desktop mode then.

Compatibility is the laptop baseline. The plan recommends Forward+ for Link; renderer/connection mode are **not frozen** until the lab test. Test `--rendering-method forward_plus` on the lab PC, then record the chosen renderer, runtime, stereo, controller and readback evidence. Native Android/MR is outside this increment.

## Capture → networking/overlay interface

`SeeSawCaptureRig.request_capture(head_pose: Transform3D, hit: Dictionary = {}) -> bool` accepts one render/readback at a time. A false return means no new capture was started. `capture_completed(CaptureSnapshot)` emits only after `RenderingServer.frame_post_draw`; `capture_failed(reason)` leaves the prior successful capture intact. This is capture-level exclusion only: G2 must also enforce one network request in flight and handle timeouts/late results.

Treat the emitted snapshot as read-only. It contains:

| Value | Convention |
| --- | --- |
| `probe_id` | Random session prefix plus monotonic sequence; bind network results to this ID |
| `rgb_png` | 224×224, RGB8 PNG, top row first; preview and PNG use the same bytes |
| `camera_transform`, `view` | Saved camera-to-world and world-to-camera transforms, in metres |
| `projection` | Dedicated square Camera3D projection; never substitute an XR-eye or current-head projection |
| `captured_usec` | Client monotonic timestamp; not backend inference time |
| `depth` | Owned image copy from B1 provider, or null while integration is pending |
| `aim_hit` | World-space `position` and `normal` as arrays of 3 numbers; empty means no hit |

JSON export lists matrix **columns**, not rows. `world_to_uv()` maps camera projection NDC to top-left UV: `(x/w * .5 + .5, .5 - y/w * .5)` and rejects points behind the camera. The overlay must additionally reject near/far/out-of-bounds points and capture-hidden surfaces. The CPU camera projection is not automatically the GPU shader's renderer-adjusted depth projection; B1 must validate this interface with the calibration and occluder tests.

`MainXR.aim_updated(hit)` emits each physics frame for Biswarup's highlight input. Empty hits must clear highlighting. `MainXR.capture_completed(snapshot)` forwards the captured context to G2/B1. G2 retains it until the response is applied or discarded, advances `match_against` only after applying a result, and resets history on scene changes. No HTTP client is included yet.

## Depth provider: handoff to Biswarup (B1)

Assign `CaptureRig.depth_provider` before capture. It is a Node owned by B1 implementing:

```text
begin_capture(camera: Camera3D, probe_id: String) -> void
finish_capture(probe_id: String) -> Dictionary
```

`begin_capture` runs before the RGB render. Copy the frozen camera transform, projection, near/far, world and 224×224 size; schedule the depth pass for the same frame. Do not modify the camera or live scenes. `finish_capture` runs after that frame's draw and returns `{probe_id, image}`. The image must be 224×224 `Image.FORMAT_RF`, top-left origin, **positive linear camera-space -Z in metres**, with far-plane distance for background. Nonfinite/nonpositive values, wrong IDs, dimensions or formats fail the capture. The rig duplicates the image so later depth frames cannot mutate it.

There is deliberately no substitute depth implementation in Gloria's files. Missing depth allows RGB development captures but `projection_ready()` is false. G2/B1 **must refuse surface projection** until it is true. B1's real depth renderer and capture-occlusion acceptance remain mandatory; synthetic test depth validates only the interface.

Gloria will instance Biswarup's DemoWorld and Yernur's child scenes through `WorldSlot`/MainXR in G3, and set MainXR's `calibration_enabled` to false. Their scenes, shaders, overlay and UI scripts are untouched.

## Verification and remaining gates

Run the rendering test on a machine with a display/GPU, from the repository root:

```text
godot --path godot --xr-mode off --script res://scripts/xr/test_capture.gd -- --desktop
```

It exits nonzero on a failed check: image dimensions/format, asymmetric colors and mid-grey, saved pose after moving the head, top-left projection, unique IDs, busy rejection/recovery, depth copy isolation and wrong-depth-ID rejection. Headless import and `--check-only` parse all scripts separately; a headless dummy renderer cannot validate actual pixels.
