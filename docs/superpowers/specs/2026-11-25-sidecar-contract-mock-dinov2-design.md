## Approaches considered (attention extraction)

| Option | Trade-off |
| --- | --- |
| **A. torch.hub `facebookresearch/dinov2` `dinov2_vits14` + hook on the last block (chosen)** | Same backbone FeatUp wraps, so features stay the same at E2. ~30 lines that depend on DINOv2's internal attention layout: pinned hub commit and a test that attention rows sum to 1. |
| B. Hugging Face `transformers` Dinov2, `output_attentions=True` | Trivial attention, stable API. A second copy of the model FeatUp won't use, large extra dependency, equivalence to prove at E2. |
| C. Load through FeatUp's hub now | Most faithful, but pulls the FeatUp install and CUDA extension question onto the Mac today, ahead of the 26 Nov lab PC check. |

**Decision:** A now. **At E2, switch the loader to FeatUp's hub and take the backbone from it; the attention hook stays.** Verify then that FeatUp's `dinov2` really wraps `facebookresearch/dinov2` `dinov2_vits14`. ## Contract draft (summary; full text goes in `docs/api.md`)

**`POST /probe`**, `multipart/form-data`:

- `image`: PNG, 224×224. RGB; RGBA accepted and alpha dropped (Godot images are often RGBA8).
- `metadata`: JSON string.

```json
{
  "schema_version": 1,
  "probe_id": "p-000042",
  "session_id": "s-7f3a",
  "models": ["dinov2_vits14"],
  "match_against": {"dinov2_vits14": "p-000041"},
  "reset_history": false
}
```

`match_against` maps model ID → probe_id of the last result the client **applied**, or null. K is fixed at 8.

**200 response:**

```json
{
  "schema_version": 1,
  "probe_id": "p-000042",
  "status": "ok",
  "mode": "real",
  "server_total_ms": 61.2,
  "results": [{
    "model_id": "dinov2_vits14",
    "width": 224, "height": 224,
    "cluster_map_png_base64": "...",
    "attention": [0.0041, 0.0032, ...],
    "attention_norm": [1.0, 0.78, ...],
    "upsampler": "nearest",
    "matched_to": null,
    "timings_ms": {"encode": 40.1, "cluster": 12.0, "featup": null, "assign": 0.4, "match": null}
  }]
}
```

- `cluster_map_png_base64`: 8-bit grayscale PNG, pixel value = group ID 0–7, top-left origin, x right, y down.
- `attention[i]`: mean over the patches of group i of last-layer CLS-to-patch attention, averaged over heads. Empty group → 0.
- `attention_norm[i]`: `attention[i] / max(attention)`; all zeros if the max is 0.
- `upsampler`: `"nearest"` (patch labels repeated over 14×14 blocks, does not satisfy A4) or `"featup_jbu"` (from E2).
- `matched_to`: probe_id the groups were matched against, or null when this result is a reset (no `match_against`, unknown ID, or `reset_history`). Lets the client detect a stale `match_against`.
- `timings_ms`: `null` for a stage that did not run. GPU work is synchronized before each stage time.
- `mode`: `"real"` or `"mock"`.

**Errors** (400 invalid input, 503 model unavailable, 500 processing error):

```json
{"schema_version": 1, "probe_id": "p-000042", "status": "error",
 "error": {"code": "invalid_input", "message": "image must be 224x224, got 256x256"}}
```

`probe_id` is null when the metadata could not be parsed. No partial results.

**`GET /health`** (Emre's addition, for connection checks): `{"status": "ok", "mode": "mock", "models": ["dinov2_vits14", "mock_model_b"], "device": "mps"}`.

## Mock server

- `python server.py --mock [--scenario NAME] [--delay-ms N] [--host 127.0.0.1] [--port 8765]`
- Validates the request exactly like real mode (bad input → 400), then answers from fixtures.
- Echoes the request's `probe_id` and returns one result per requested model: `dinov2_vits14` and `mock_model_b` exist; any other model → 503.
- Keeps a small history like real mode: in `valid`, `matched_to` echoes `match_against[model]` if the mock served that probe_id in this session, else null (so Gloria's bookkeeping can be tested against realistic behavior).
- Scenario from `X-Mock-Scenario` header, else `--scenario`, else `valid`:

| Scenario | Response |
| --- | --- |
| `valid` | 200, results for requested models |
| `invalid_labels` | 200, cluster map contains value 9 (client must reject) |
| `wrong_id` | 200, `probe_id` differs from the request (client must discard) |
| `stale` | 200, `matched_to: null` although `match_against` was sent |
| `failure` | 500 `processing_error` |
| `unavailable` | 503 `model_unavailable` |

- `--delay-ms` (Emre's call): sleeps before answering so Gloria can test busy state, late results and timeouts (A10, A11) without a slow model.

## Fixtures

Generated by `sidecar/tools/make_fixtures.py`, outputs committed under `sidecar/fixtures/contract/`:

1. `one_model_valid.json`: synthetic asymmetric map (distinct blocks per group, marker in the top-left corner, not symmetric under flips).
2. `paired_valid.json`: model A = real DINOv2 on `image1`, model B (`mock_model_b`) = synthetic map.
3. `invalid_labels.json`, 4. `wrong_id.json`, 5. `stale_match_against.json`, 6. `service_failure.json`.

Regenerating the paired fixture needs torch; the others do not. A light test checks every fixture: valid PNG, 224×224, values in range (except `invalid_labels`), 8 finite attention values.

## Real pipeline

1. Decode and validate the image (224×224; RGB or RGBA).
2. ImageNet normalization; forward through `dinov2_vits14` (pinned hub commit); take the 256 patch tokens (16×16 × 384) and L2-normalize them.
3. Forward hook on the last block's attention module computes softmax(q·kᵀ/√d) for the CLS query, averaged over the 6 heads; keep the 256 patch entries.
4. scikit-learn `KMeans(n_clusters=8, n_init=10, random_state=0)` on the patch features.
5. Relabel groups by image-space height (mean row of the group's patches, top = 0), as the paper does (Findings, p.2), so the same image gives the same IDs before matching exists.
6. Group attention (raw and normalized), nearest upsample to 224×224, encode PNG.
7. Store the centroids in the history: per `(session_id, model_id)`, last 10 probes; `reset_history` clears the session. Matching is E3; `matched_to` is always null today.

Inference runs in a worker thread behind a lock (one in-flight model call), so the server stays responsive. Device: `--device auto` picks cuda, then mps, then cpu. Model weights live in the torch hub cache, never in the repo.

The numpy-only steps (relabel, group means, normalization, upsample, PNG encoding, validation) live apart from torch code, so CI tests them.
